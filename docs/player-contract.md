# 再生窓（player）の契約

claude-speak は「本体（speak.sh）→ 合成（synth/）→ 再生窓（player/）」の 3 層で、OS ごとに違うのは再生窓だけです。
Mac や Linux で使うには、この文書の契約を満たす `player/<os>.sh`（と、そこから起動する窓の実装）を追加してください。
`<os>` は `uname -s` が Darwin なら `mac`、WSL なら `windows`、それ以外の Linux なら `linux` です（`config.env` の `PLAYER=` で上書き可）。

## アダプタ `player/<os>.sh` のインターフェース

| 呼び出し | 役割 |
| --- | --- |
| `<os>.sh workdir` | 作業フォルダの絶対パスを標準出力に 1 行で返す。窓の実装から読める場所であること（例：`${TMPDIR:-/tmp}/claude-speak`） |
| `<os>.sh start <作業フォルダ>` | 窓をバックグラウンドで起動し、すぐに戻る（ブロックしない） |
| `<os>.sh stop <作業フォルダ>` | 起動中の窓を止める。起動していなくてもエラーにしない |

本体は `start` の直前に合成プロセスを起動済みで、作業フォルダには `chunks.txt` と `label.txt` が置かれています。
音声ファイルは合成の進行に合わせて後から増えます。

## 作業フォルダの中身

| ファイル | 書く側 | 内容 |
| --- | --- | --- |
| `chunks.txt` | 本体 | 読み上げる文。1 行 1 文、UTF-8。行番号 i（0 始まり）が音声 `NNN` に対応 |
| `label.txt` | 本体 | 見出しに出す作業ディレクトリ名（どのセッションの回答か） |
| `NNN.mp3` | 合成 | i 番目の文の音声（`000.mp3`, `001.mp3` …）。書きかけは `.tmp` で、完成後にリネームされるので存在すれば完全 |
| `NNN.dur` | 合成 | i 番目の音声の長さ（秒、小数）。`NNN.mp3` より先に置かれる |
| `done` | 合成 | 全文の合成が終わった印（失敗時も置かれる） |
| `player.pid` | 窓 | 窓のプロセス ID。`stop` が参照する。窓を閉じるときに消す |

## 窓に求める振る舞い

- `NNN.mp3` を 0 番から順に、存在し次第再生する。次がまだ無ければ「生成中…」を表示して待つ（200ms 程度のポーリングで十分）
- 全チャンクを再生し終え、かつ `done` があれば自動で閉じる。`done` があるのに次のチャンクが存在しない場合（合成失敗）も閉じる
- 全体の進捗バー：長さは「`.dur` が分かっているチャンクの合計 ＋ 未生成チャンクの推定（文字数 × 0.17 秒）」。チャンクが増えるたびに更新する
- 位置の計算：再生済みチャンクの長さの合計 ＋ 現在チャンク内の位置。シークはこの全体秒を受け取り、チャンク境界をまたいで解決する。未生成領域へのシークは生成済み末尾に丸める
- 操作：進捗バーのクリックとドラッグでシーク、5 秒戻る、再生／一時停止、5 秒進む、停止（閉じる）
- 表示：見出し「Claude 読み上げ · <label.txt の内容>」、読んでいる文（`chunks.txt` の該当行）、現在位置／全体長、「n / m」（文番号／文数）
- 常に手前に表示し、画面の邪魔にならない大きさで、ドラッグで移動できること

参考実装は `player/windows.ps1`（WPF）と `player/windows.sh` です。
